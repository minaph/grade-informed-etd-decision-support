# 意思決定を軸とする実務応用

状態：採用。決定日：2026年9月15日。

## 決定

このスキルは、日常的な話題や多分野の話題を、基本的に意思決定として扱います。実際の行動を選ぶことに加え、知的な話題について、どの理解・説明の立場をとるか、どの概念定義を採用するかを判断の対象とします。

概念モデリング技術を実務へ応用するという目的は維持します。その実務的関心に応えるための手段として、対象を意思決定として捉え、状況の整理、概念の定義、評価、説明をつなぎます。

## 採用理由

日常生活や専門分野では、求められる成果が行動案とは限りません。説明の仕方や対象の数え方を決めることも、その後の理解、記録、議論に影響します。例えば、地域イベントの「主催者」「運営担当」「協力者」を整理する依頼では、人と役割をどう区別し、兼任をどう表すかという定義上の判断が必要です。採用したモデル定義そのものが依頼への回答になります。

こうした判断を含めることで、概念モデリングの成果を、何のために採用し、どの条件で使うかという実務の関心へ接続できます。この立場は親スキルの用途を定める設計上の選択であり、あらゆる知的活動の本質についての主張ではありません。

## 適用範囲と限界

理解・説明の立場を含めても、依頼に即した判断の対象が成立しない非・意思決定的な関心には、このスキルは助力できません。非・意思決定的な用途を別の支援経路として親スキルに設けることはしません。この制限は、独立した概念モデリング技術や文章作成技術の用途には及びません。

このスキルは、ユーザーの指示の背後にある意思決定構造を推定し、それに基づいて推論や調査を展開します。指示に明示されていない行動目標、利用者の価値、選択肢も、解釈の仮説として積極的に補います。Narrative Upscaling は、その推定を背景情報、経験、具体例、学習支援の探索へつなげる規則です。推定は利用者が述べた事実や確定した意向と区別し、複数の解釈や訂正を受け入れる形で扱います。

このため、このスキル自身が自らの適用範囲を判定することには限界があります。明示的な意思決定が見つからないことや、最初の解釈で目的を特定できないことだけでは、対象外にできません。ユーザーの指示が詳細になり、非・意思決定的な解釈を要求していることが明確になって初めて、適用範囲から除外できます。

短い回答やコマンドだけを求める指示は、出力形式の制約です。それだけで背後の意思決定の探索を否定する指示とはみなしません。一方、ユーザーが推定した目標や価値を否定した場合は解釈を更新し、明確に求められた非・意思決定的な解釈を、別の潜在目的の推定によって覆しません。

理解の立場を選ぶことと、事実の真偽を確かめることは区別します。説明の目的に合う観点を採用しても、反する証拠を省いたり、未確認の事実を確定したりする理由にはなりません。根拠が足りない場合は、判断の保留や条件付きの立場も成果になります。

## 運用への反映

`SKILL.md` には、話題を意思決定として扱う指示と適用境界を記載します。この立場を選んだ理由は、ルート README とこのディレクトリで扱います。既存の規則の由来と設計課題の記録も `references/` から移し、通常の参照手順から外します。

意思決定構造化は、理解や定義の採用に必要な区別も扱います。内部の探索と利用者に見せる出力は分け、明示された簡潔さや固定形式の制約を守ります。短い指示からも潜在的な目的を推定し、役立つ比較や助言を展開できますが、短さだけを理由に一律の拡充は行いません。

Generic EtD は評価と報告が必要な場合に用いるモデルの一つです。意思決定として扱うことから、毎回の EtD レポート作成は導きません。Narrative Upscaling は背景や具体例などを加える別規則として維持し、文章の作成・推敲には独立した文章スキルを使います。

## 再検討する点

知的な話題で必要な判断を捉えられず、単なる情報の列挙に終わる場合や、推定した意思決定構造が利用者の訂正や明示的な制約を無視した比較・提案を生む場合は、適用例と指示を見直します。非・意思決定的な関心と、簡潔な形式で判断を表す依頼との境界も、具体例に照らして点検します。今回の文書化は設計方針の確定であり、モデルの応答品質の改善を実証したものではありません。
