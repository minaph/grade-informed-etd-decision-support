# レポートモデルと運用指示の分離

状態：モデル分離は採用。運用指示の配置は [一般手順への統合](general-routing.md) により更新。決定日：2026年9月15日。

以下はモデル分離時の判断記録です。当初 Narrative Upscaling に置いた運用は、現在は SKILL.md に統合しています。

## 決定と理由

Narrative Upscaling に混在していた記述内容の定義を、共通のレポート構成と、関係・分類、出来事・経験、用語、学習、成果物・手順の利用説明の計6モデルへ分けます。各モデルは、何を一件と数え、どの概念を区別し、どう関連づけて報告するかを自然言語で定義します。

これらは現行の回答作成上の経験則を整理したモデルであり、普遍的な分類体系や、効果を実証済みの報告形式ではありません。共通モデルを必須の基底にせず、個別モデルだけでも目的、構成要素、根拠と限界、記述方法を理解できるようにします。中心・補足は回答内の役割、文章・画像・コードは媒体として区別します。

Generic EtD との固定の項目対応や継承関係は設けません。個別モデルはそれぞれの説明を成立させ、評価・推奨が必要な場合の併用は Narrative Upscaling 側で扱います。経験が回答の中心となることもあるため、個別モデルを評価レポートの補足欄に限定しません。

## 実装前レビューでの合意

Astra medium とモデル作成前に境界を検討し、6モデルの構成に合意しました。指摘された次の3点を採用しています。

- 単独利用に必要な根拠・不確実性の扱いを各モデルに短く定義する。共通モデルや Generic EtD の参照を必須にしない。
- 成果物だけでなく手順・期待結果・確認された結果も扱い、依頼された行為の遂行は運用側に保持する。
- モデル選択と調査を固定の一方向の順序にせず、暫定選択と情報収集、解釈の更新を往復する。

単独利用に必要な短い定義の重複は認めます。全項目の記入、必須の練習問題、新しい保存スキーマは設けません。

## 運用への影響と確認

Narrative Upscaling には、潜在的な目標・価値の仮説補完、モデルの暫定選択、調査・聞き取り、必要時の併用、回答と終了判断を残します。モデル内の概念定義は運用指示へ複製しません。利用者の意向と仮説の区別、回答のみ・コマンドのみの指定、事実と実行結果の正確な報告を維持します。

各モデルには架空の適用例、境界、能力質問を置きます。既存の回答拡充6ケースを維持し、単独適用の評価定義を追加します。定義の検査と実際の応答品質の評価は区別し、反復実験による性能改善は主張しません。

今後は、単独利用時の不足、併用時の重複、モデル項目の過剰な表示、推定した目的からの探索不足を事例で確認します。共通化を進める場合も、利用のたびに多数の文書を読む必要が生じないかを確かめます。
