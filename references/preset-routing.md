# 概念モデルの選択と事例への適用

この文書は、候補モデルの適合性、意味の境界、改訂の必要性を詳しく検討する際の指針です。通常の候補選択は親スキルの一般手順と、モデルファイル冒頭のメタデータを使います。エージェントは、モデルの表現能力と事例の情報を確認し、採用するモデル、補う情報、必要な改訂を判断します。個別の参照モデルの定義や改訂方針には、それぞれの管理規則を適用します。

モデル定義や理解・説明では、依頼の目的に照らしてどの定義や説明の立場を採用するかを判断します。採用した定義や適用結果は、それ自体を成果物として返せます。意思決定の問い（Questions）には判断に必要な区別を反映し、選択肢の形成（Formation）や意思決定評価（EtD）は、その判断に必要な範囲で行います。依頼と無関係な行動提案や比較は追加しません。

立場や行為の評価・比較・推奨を報告する場合は [Generic EtD モデル](models/generic-etd-model.md) を参照します。
評価項目と報告方法の定義は同文書に集約し、この文書ではモデルの選択・適用・改訂を扱います。

## 1. 親スキルとモデリングスキルの役割

親スキルは、用意された参照モデル（プリセットモデル）と能力質問（CQ）を管理し、目的に合うモデルの採用と成果物への反映を判断します。状況の記述（Context）と意思決定の問い（Questions）を整理し、採用したモデルを選択肢の形成や評価に使います。

概念モデリングスキルは、渡された目的・資料・実例・定義に基づいて、聞き取り、適用評価、定義、改訂を進めます。親スキルは、その成果を選択肢の形成（Formation）や意思決定評価で使える形に整理します。この役割分担によって、概念モデリングスキルは他の用途でも単独で利用できます。

通常の適用では、採用したモデルの定義に従って記録を作ります。適合性や意味の境界を調べる場合、または定義を変更する場合は、`skills/conceptual-modeling/SKILL.md` の手順を使います。

依存先は、親スキルで固定した版を参照します。取得が必要な場合は、READMEのサブモジュール（submodule）取得手順に従います。この文書の `skills/` と `references/` は親スキルのルートから、概念モデリングスキル内の参照はそのスキルのルートから解決します。

## 2. 能力質問と意思決定の問いを対応づける

能力質問は、モデル定義に付随する表現要件です。モデルが何を区別し、どのような問いを扱えるべきかを示します。意思決定の問いは、現在の状況と作業目的に属し、どの違いが選択肢や行動を変えるかを示します。記録には、前提（`premise`）、分岐となる区別（`splitter`）、候補となる行動（`actions`）を使います。

モデルを選ぶ際は、意思決定の問いが必要とする対象・関係・条件を、能力質問を具体化した問いとして表せるか確認します。この文書では、その関係を「包含」と呼びます。包含は、必要な意味が保たれるかを確かめるための対応づけです。文章の類似度や質問の件数よりも、モデルが実際に表現する区別を重視します。

対応づけでは、次の三点を分けて確認します。最初の二点はモデルの適合性を、三点目は事例の情報状態を確かめるために使います。

| 確認する観点 | 確かめること |
| --- | --- |
| 要求の対応 | 意思決定の問いに必要な区別が、能力質問の対象に含まれるか |
| 定義の裏付け | 概念・関係・属性が、その区別を表現できるか |
| 事例の情報 | 今回必要な値や根拠が得られているか |

能力を確認するときは、対応する定義と検証結果を示します。能力質問に記載されていない問いについても、モデル定義を確認し、説明の不足と構造の不足を分けます。必要に応じて、具体化した問いを既存の事例へ適用して確かめます。

一つの意思決定の問いを複数の能力質問が支える場合も、一つの能力質問から複数の事例の問いが生じる場合もあります。モデルは情報上の区別を表します。利用者の価値や許容する条件は、明示されていない段階では仮説を置いて探索に使い、判断を左右する場合は事例側で確認します。複数モデルを使う場合は、それぞれが担う区別を示し、成果物に適用される組み合わせの規則に従います。

例えば、能力質問が「移行方式ごとの復旧条件・所要時間・データ損失を比較できるか」で、今回の条件が「停止可能時間は30分」であるとします。この場合は、時間・損失・条件を表現できるか確認します。「可逆性：高・中・低」という分類に加えて、時間や損失の値が必要になる場合があります。構造が十分で実測値が未取得なら、情報収集を次の作業にします。30分という条件の根拠は、事例側で確認します。

## 3. 候補の比較と問いの整理を繰り返す

### 3.1 状況と用途から候補を絞る

状況の記述、暫定的な意思決定の問い、利用目的、既存資料から、候補となるモデルを選びます。候補の対象・状況・目的・除外条件を照合し、適用範囲と、判断に必要な詳しさを比較します。新しいモデルが適する場合は、事例に即した仮定義から始めます。

候補ごとに、何を一件と数え、どの単位で比較するかを確認します。実例への適用と候補の比較を繰り返し、重要な違いを保てる構成を選びます。

### 3.2 重要な問いを能力質問と定義へ照合する

第2節の三点に沿って、十分に表現できる区別、部分的に表現できる区別、能力が未確認の区別、対象外の区別を整理します。候補の採否では、判断を変え得る区別を必要な詳しさで扱えることを優先します。

### 3.3 候補から見落としを点検する

候補の能力質問や定義から、新しい重要な論点が見つかることがあります。選択肢や条件を変える論点は、状況の記述または意思決定の問いへ反映し、候補を再評価します。参照モデルは、このように検討事項の不足を点検するために使います。事例の事実と根拠は資料で確かめ、価値判断では利用者が示した意向と、探索のために推定した価値を区別して記録します。

状況の記述と意思決定の問いを更新した後は、`references/question-formation.md` に従って分岐図（Tree）と選択肢を再生成します。能力質問との重要な対応や不足は、補足の文章として記録します。形成用の記録には既存の形式を用います。

## 4. 差分の影響から対応を選ぶ

モデルの不足や候補間の違いは、意思決定への影響に照らして評価します。次の観点から、どの判断が変わるかを示します。

- 成立する選択肢と、その実現可能性。
- 必要な根拠、その解釈、追加確認。
- 価値、リスク、受容性、資源、実施条件。
- 結論、結論に付す条件、再評価の必要性。

対応は、不足しているものが情報か構造かによって選びます。局所的な補足で目的を満たせる場合は、その意味と影響を確認して採用します。

| 状況 | 対応 |
| --- | --- |
| 適用範囲と詳しさが合い、重要な区別を保てる | 現行モデルを採用します |
| 表現でき、値や根拠の追加収集が必要 | 個別の記録に未確認などの状態を示し、判断への影響に応じて確認方法を選びます |
| 既存の意味を保つ補足で目的を満たせる | 理由と影響を示して局所的に補い、再評価します |
| 構造や相互作用の不足が判断を変え得る | モデリングスキルの手順で、事例固有の定義・拡張・再設計を検討します |
| 一部の問いに適合する | 適用する部分と、残りの問いを扱う方法を示します |
| 対象や意味を保った適用が困難 | 候補から外し、別のモデルや事例固有モデルを検討します |

対象の単位や既存の意味を変える補足は、定義変更として扱います。「暫定属性」と呼ぶ場合も同様です。複数の定義を組み合わせる際は、各定義の意味と情報状態を引き継ぎ、成果物に適用される組み合わせの条件を確認します。

重要な情報不足については、確認する内容、方法、その方法を選ぶ理由、結果によって変わる判断を記録します。調査（Research）と聞き取り（Interview）は、必要な情報の性質に応じて選びます。聞き取りの時期は、親スキルの選択肢形成の手順に合わせます。

## 5. 事例へ反映し、次の行動を決める

採用したモデル定義と、その定義に照らした事例の値を分けて記録します。複数の表現をまとめる場合も、採用した意味、重要な出所、値の確定性を保ちます。記録方法は、これらを説明しやすい文章や表を選びます。

親スキルは、モデリングスキルの成果を、依頼されたモデル定義や事例の適用結果へ反映します。情報・制約・不確実性を状況の記述へ、重要な分岐を意思決定の問いへ反映します。変化が重要なら分岐図と選択肢を再生成し、意思決定評価への影響を確認します。モデルの表現能力と、回答や推奨を支える根拠は、それぞれの確認結果を示します。

作業の完了には、参照モデルまたは依頼元が定めた条件を優先します。固有の条件がない場合は、必要な区別を表現でき、残る不確実性を説明でき、追加のモデル変更を検討しても結論や条件が安定していることを確かめます。完了時には、採用理由と再検討の条件を示します。残件がある場合は、能力不足・情報不足・要件未決のどこに課題があるかを報告します。

共有モデルへの反映では、観察、改訂候補、改訂案、正式反映を分けて進めます。再利用の提案では、成立条件・再発性・抽象化可能性を調べます。中心的な定義の誤りを示す反例は、一例でも改訂を検討する根拠になります。正式な反映は、対象モデルの管理・承認・版管理の規則に従います。
