# レポート構成モデル

## 目的と単位

読者が主題への回答を理解し、必要な場面で利用できるよう、記述の役割と相互関係を整理するモデルです。一件は、ある読者・目的・主題に対する一つの回答または報告です。一文の回答にも、複数節からなる文書にも適用できます。

このモデルは、説明や報告を作る際の経験則を自然言語の概念定義として整理したものです。固定の章立てや保存形式を要求しません。以下の要素は、伝える意味に必要な範囲で使います。

## 構成要素と関係

| 概念 | 定義 |
| --- | --- |
| 主題と中心的な回答 | 何を扱い、その問いについて何を伝えるか。成果物の提示も回答に含む。 |
| 読者の目的と前提 | 何のために読み、何を既に知り、どの条件で利用するか。明示された内容と作成者の仮説を区別する。 |
| 記述単位 | 一つの主張、説明、例、条件など、回答内で意味上の役割を持つまとまり。文や段落の数とは一致しなくてよい。 |
| 役割と貢献 | 記述が、回答、根拠、背景、区別、具体化、条件、利用・学習への接続などの何を担い、読者の何を助けるか。 |
| 根拠と適用範囲 | 主張を支える資料・観察・推論と、その成立する対象・場面・時点。不明や競合も必要に応じて示す。 |
| 表現媒体 | 文章、表、図、画像、コードなど、記述を伝える形。例や根拠といった意味上の役割とは区別する。 |

記述単位は、他の記述を裏付ける、具体化する、限定する、対照する、利用へつなげるなどの関係を持ちます。一つの記述が複数の役割を担う場合もあります。説明の観点は中心的な回答の意味を定め、例や経験はその観点で重要な区別を具体化します。

「中心」と「補足」は、その回答内での役割です。経験を知りたい依頼では経験の記述が中心となり、別の依頼では同じ経験が補足になります。画像であることだけから、経験の証拠であるとは判断できません。

## 記述方法

中心的な回答を把握できる位置に置き、読者に必要な根拠、背景、具体例、条件を関連づけます。関係が明らかな場合は「この段落の役割」のような説明を付けず、文章自体でつながりを示します。説明を充実させるために、存在しない対立や不確実性を作りません。

資料にある主張、作成者の解釈、説明用の作例を区別します。目的を推定して記述を組み立てる場合は、結論を左右する仮説を条件として示し、読者が訂正できるようにします。根拠が不足する箇所は、何が分からないかと回答への影響を伝えます。

記述の採用は、誤解を解く、重要な違いを説明する、利用や学習を助けるなどの貢献によって判断します。すべての役割を埋める必要はありません。明示された文字数や形式を守り、短い回答にも重要な限定を残します。

## 適用例と境界

架空例として、「催しの入場方法」を説明する文書に「予約が必要」という回答と、予約画面の図を載せる場合を考えます。図が操作箇所を示すなら利用の説明であり、予約義務の根拠は規定の記述です。同じ図を根拠として扱えるかは、図に何が示されているかで変わります。

このモデルは文章内の関係を表しますが、主張の真偽や、どの選択肢を推奨すべきかを自動的に決めるものではありません。

## 定義を確かめる問い

- ある記述が、どの回答や読者の目的に、どう貢献するかを表せるか。
- 内容上の役割と表現媒体、確認済みの内容と仮説を区別できるか。
- 短い回答でも、中心的な意味と必要な限定を表せるか。
